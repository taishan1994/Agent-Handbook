## 1. 中间件基础概念

中间件是 Agent 执行流程中的拦截器，可以在特定时机介入并处理数据。LangChain 的中间件需要继承 `AgentMiddleware` 基类。

## 2. 核心结构

### 2.1. 基类继承
```python
from langchain.agents.middleware import AgentMiddleware, AgentState
from langgraph.runtime import Runtime

class YourMiddleware(AgentMiddleware):
    name = "your_middleware_name"  # 中间件名称
```

### 2.2. 关键生命周期钩子

中间件提供多个钩子方法，在不同阶段执行：

**在模型调用前/后：**
- `wrap_model_call()` - 同步版本，包装模型调用
- `awrap_model_call()` - 异步版本，包装模型调用
- `after_model()` - 模型调用后处理
- `aafter_model()` - 异步版本的模型后处理

**在工具调用前/后：**
- `before_tool()` - 工具调用前处理
- `abefore_tool()` - 异步版本
- `after_tool()` - 工具调用后处理
- `aafter_tool()` - 异步版本

## 3. 实际案例解析

### 3.1. 案例 1: TextToolCallsMiddleware

这个中间件用于解析文本格式的工具调用：

```python
class TextToolCallsMiddleware(AgentMiddleware):
    name = "text_tool_calls"

    def after_model(self, state: AgentState, runtime: Runtime[Any]) -> dict[str, Any] | None:
        """在模型调用后，检查并转换文本格式的工具调用"""
        messages = state["messages"]
        if not messages:
            return None

        last_message = messages[-1]
        
        # 只处理 AIMessage
        if not isinstance(last_message, AIMessage):
            return None
        
        # 如果已经有结构化的 tool_calls，不需要处理
        if last_message.tool_calls:
            return None
        
        # 解析工具调用
        tool_calls = self._parse_tool_calls(content)
        
        if not tool_calls:
            return None
        
        # 创建新的 AIMessage，包含结构化的 tool_calls
        new_message = AIMessage(
            content=content,
            tool_calls=unique_tool_calls,
            ...
        )
        
        # 返回更新后的消息列表
        return {"messages": Overwrite(new_messages)}
```

**关键点：**
- 在 `after_model` 钩子中处理模型输出
- 检查并转换文本格式的工具调用为结构化格式
- 使用 `Overwrite` 包装器替换整个消息列表
- 返回 `None` 表示不修改状态

## 4. 使用中间件

在 agent.py 中使用：

```python
text_tool_calls_middleware = TextToolCallsMiddleware()
todo_list_middleware = TodoListMiddleware()

agent = create_agent(
    model=llm,
    tools=tools,
    system_prompt=system_prompt,
    middleware=[
        text_tool_calls_middleware,
        todo_list_middleware,
    ],
    debug=False
)
```

## 5. 构建自定义中间件的步骤

1. **继承基类**：`class YourMiddleware(AgentMiddleware)`
2. **定义名称**：`name = "your_name"`
3. **选择钩子**：根据需求选择合适的生命周期方法
4. **处理状态**：访问和修改 `state["messages"]` 等数据
5. **返回更新**：返回 `dict` 更新状态，或 `None` 不修改
6. **注册工具**（可选）：在 `__init__` 中添加 `self.tools`
7. **扩展状态**（可选）：定义 `state_schema`

## 6. 常见模式

- **转换数据**：在 `after_model` 中转换消息格式
- **验证约束**：在 `after_model` 中检查工具调用
- **注入工具**：在 `__init__` 中注册自定义工具
- **修改提示**：在 `wrap_model_call` 中修改系统消息
- **状态管理**：通过 `state_schema` 添加自定义状态

这就是构建中间件的核心方法，通过在不同生命周期钩子中插入自定义逻辑，可以灵活地扩展 Agent 的功能。
