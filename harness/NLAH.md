Natural-Language Agent Harnesses

https://arxiv.org/pdf/2603.25723

这是一篇关于人工智能代理（AI Agent）系统架构的深度解读。这篇论文《Natural-Language Agent Harnesses》（自然语言代理套件）由清华大学深圳国际研究生院和哈尔滨工业大学（深圳）的研究团队发表。

论文提出了一个极具创新性的观点：**将代理的“控制逻辑”从代码中解放出来，直接用自然语言编写和执行**。这不仅是工程实践的改进，更是一次关于“如何将代理架构作为科学对象进行研究”的范式转移。

以下是对这篇论文核心内容的详细解读：

### 1. 核心痛点：被埋没的“套件”逻辑
在当前的代理系统中，决定其成败的关键往往不是模型本身，而是围绕模型的**“套件”**（Harness）。这个套件包含了控制流（如思维-行动循环）、记忆管理、工具使用、验证机制等复杂的控制逻辑。

然而，目前的现状存在三大问题：
*   **难以迁移**：套件逻辑通常被硬编码在特定的运行时代码中，无法直接在不同系统间移植。
*   **难以比较**：由于缺乏统一标准，比较两个代理的差异往往变成了比较两坨完全不同的代码包（Bundle），无法精准定位是哪个模块导致了性能变化。
*   **难以研究**：套件逻辑被隐藏在代码深处，无法作为一个独立的“科学对象”进行分析和抽象。

### 2. 核心方案：NLAH 与 IHR
为了解决上述问题，论文提出了**自然语言代理套件**（NLAHs）和**智能套件运行时**（IHR）的架构。

#### 2.1 自然语言代理套件 (NLAH)
NLAH 是一种结构化的自然语言表示，它将代理的控制逻辑直接写在文本中。它不是简单的注释，而是可执行的蓝图，必须包含以下显式组件：
*   **契约 (Contracts)**：输入输出要求、预算、权限边界。
*   **角色 (Roles)**：定义不同的角色（如解决者、验证者、研究者），并明确其非重叠的责任。
*   **阶段结构 (Stage Structure)**：显式的工作流拓扑（如计划→执行→验证→修复）。
*   **适配器与脚本**：用于确定性操作的钩子（如测试、检索）。
*   **状态语义**：定义跨步骤持久化的数据及其路径。

#### 2.2 智能套件运行时 (IHR)
IHR 是一个共享的运行时环境，它内部包含了一个循环中的 LLM。它的职责是读取 NLAH，并根据运行时宪章（Charter）、当前状态和环境，解释并执行下一步动作。
*   **模型调用 vs. 代理调用**：IHR 将单一的模型调用提升为受契约约束的代理调用。
*   **分离关注点**：IHR 负责通用的运行时服务（如工具调用、沙箱），而 NLAH 负责具体的任务逻辑。

### 3. 关键创新：文件支持的状态模块
为了解决长程任务中状态丢失的问题，论文引入了一个可选的**文件支持的状态模块**（File-Backed State Module）。
*   **显式化**：状态不再仅存在于短暂的上下文中，而是写入文件。
*   **路径可寻址**：后续阶段可以通过确切的路径重新打开对象。
*   **压缩稳定**：状态能够经受住上下文截断、重启和委托，确保了长程自治的稳定性。

### 4. 实验验证与结果
研究团队在编码（SWE-bench Verified）和计算机使用（OSWorld）两个基准上进行了验证，提出了三个研究问题（RQ）：

#### 4.1 RQ1：行为效应 (Behavioral Effect)
*   **发现**：在固定预算下，共享的运行时宪章和特定于基准的套件逻辑显著改变了代理的行为。
*   **数据**：在 TRAE 和 Live-SWE 实验中，完整的 IHR 设置虽然在解决率上波动不大，但显著增加了 Token 使用量、LLM 调用次数和运行时间。
*   **结论**：这证明了 IHR 不仅仅是一个提示词包装器，它确实引入了多阶段探索、候选比较和额外的验证行为。

#### 4.2 RQ2：可组合性 (Composability)
*   **发现**：显式化的模块（如自我进化、多候选搜索）可以被组合和剥离。
*   **洞察**：模块的效果通常集中在少数边界案例上。
    *   **自我进化 (Self-Evolution)**：效果最好，因为它收紧了解决循环，迫使代理在失败信号出现前保持搜索窄而深。
    *   **动态编排**：往往只是替换了已解决的问题集，而没有扩展解决问题的边界。

#### 4.3 RQ3：代码到文本的迁移 (Migration)
*   **发现**：将原生代码套件（如 OS-Symphony）迁移到 NLAH 后，虽然逻辑相似，但可靠性机制发生了“拓扑迁移”。
*   **变化**：原生代码倾向于基于 GUI 的修复循环（检查屏幕、选择对象），而 NLAH 实现倾向于基于文件和工件的验证（写入文件、重新打开文档、系统查询）。
*   **结果**：在 OSWorld 上，NLAH 迁移版本的得分（47.2）甚至高于原生代码版本（30.4），因为它从脆弱的 GUI 修复转向了更可靠的运行时状态和工件支持的关闭机制。

### 5. 总结与意义
这篇文章的核心贡献在于**将“套件工程”提升为“套件科学”**。

它证明了自然语言不仅仅是编写提示词的工具，当配合智能运行时（IHR）时，它可以成为一种**可执行的、可移植的、可分析的系统架构载体**。这为未来的研究提供了新的路径：我们可以不再仅仅通过编写代码来优化代理，而是通过搜索、组合和优化自然语言表示的控制逻辑来构建更强大的 AI 系统。
